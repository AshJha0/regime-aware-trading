regime-aware-trading

A four-language reference implementation (Python reference, C++, Rust, Java) of a regime-aware trading study: a diagonal-covariance Gaussian hidden Markov model — scaled forward-backward, deterministic Baum-Welch EM, Viterbi decoding, AIC/BIC model selection — fitted walk-forward on a market index and used to gate time-series momentum and an FX carry basket through a shared no-lookahead backtest engine. Initialisation, convergence semantics, the dead-state guard, label ordering, rebalance schedules, accounting and validation are all pinned in API_SPEC.md, no library code uses an RNG, and all four ports reproduce 20 golden cases (77 scalars) to 1e-6..1e-8.

What the latest review found and fixed. Baum-Welch's M-step divides by the posterior mass of each state; a state that loses all support (for example a warm start parked far from the data) produced a 0/0 and let NaN parameters leave fit. The review pinned a dead-state guard in every port — after each E-step the transition-row support is compared with 1e-12, and EM stops before the M-step with the just-scored finite parameters, converged = False and dead_state = i, so the reported log-likelihood is always the exact score of the returned parameters — plus a monotone flag, parameter/shape validation on every inference call, zero-normaliser errors, wipe-out and date checks. It also added the synthetic carry_rerank_* golden cases, which are the only golden protection for the ranking/rebalance path: the bundled carry differentials never change rank, so the demo basket built on day 0 is held for all 2000 days. golden.json was regenerated to 20 cases / 77 scalars with all 47 previous scalars bit-identical. Note also that the demo's full-sample metrics include 251 days with no momentum position and 503 days before the first walk-forward fit.

What's inside

Gaussian HMM

hmm.py and its ports: diagonal-covariance Gaussian emissions (D = 1, 2; K ≥ 2), scaled forward-backward with per-step normalisers and an emission shift, filtered and smoothed state probabilities, log-space Viterbi with a pinned tie-break, a pinned power-method stationary distribution, and log-likelihood / AIC / BIC for K = 2 vs 3 model selection. Zero forward normalisers are errors, never NaN.

Baum-Welch EM, pinned

Deterministic, RNG-free: quantile initialisation (Hyndman-Fan definition 7), Bilmes' Gaussian M-step with the t ≤ T−1 transition denominator, a variance floor, states relabelled by ascending mean, a dead-state guard and converged / dead_state / monotone flags on the fit result. Non-convergence at max_iter is reported, not thrown; the returned parameters are always finite.

Strategies

strategies.py: time-series momentum (Moskowitz-Ooi-Pedersen) with a 252-day signal, RiskMetrics EWMA vol targeting and a 4× leverage cap; an FX carry basket (Lustig-Roussanov-Verdelhan style) long the top-3 and short the bottom-3 rate differentials, rebalanced every 21 days with index tie-break; and the walk-forward regime gate that scales positions by the filtered P(calm) — the calm state re-identified by lowest variance at every refit — with warm-started refits every 63 days.

Backtest engine

backtest.py: pinned accounting with positions decided at the close and earning the next day's return, one-way costs in basis points of notional turnover charged on the trade date, and seven metrics — annualised return and vol, raw Sharpe, max drawdown, Calmar, hit rate, worst month — plus a crisis-state attribution table keyed to the fitted K = 3 model. A wipe-out (net[t] ≤ −1) names the day and raises.

Data & pipeline

data/ holds 2000 trading days generated from a true 3-state regime model (calm-bull / choppy / crisis): the market index, 6 futures-like trend assets, 6 synthetic currencies with spot returns and rate differentials, the generator's true state path for teaching comparison, and a pinned config.json. pipeline.py runs model selection, the fit, the six strategy variants and attribution end to end; generate_data.py rewrites CSVs and goldens byte-for-byte reproducibly.

Golden suite & testing

Five mirrored layers per language: ground truth by enumeration, mathematical properties (monotone EM, stochastic rows, stationarity, chained forward_step equals the full pass, costs never help, the accounting identity, the no-lookahead shift), the 20-case / 77-scalar golden file with baked-in sign and semantic invariants (crisis momentum return < 0, filtered combined Sharpe higher and drawdown shallower, re-rank panel flips at day 21), edge cases, and robustness (dead state, zero-likelihood data, malformed warm starts). C++ parses the JSON with a hand-rolled reader, Rust with serde_json, Java with a bundled parser.

Validation & error contract

Same rules and error family everywhere — ValueError, std::invalid_argument, Err(RegimeError::InvalidInput), IllegalArgumentException: empty inputs, NaN/inf, K/D and positions/returns/dates shape mismatches, non-stochastic parameters, returns ≤ −1, negative costs, K < 2, T ≤ K, thresholds outside [0, 1], labels outside [0, K), duplicated or unsorted dates. Rust never panics on library input; Java never throws ArrayIndexOutOfBoundsException from a public method.

Units, timing, scope

Simple daily returns; annualised simple rate differentials accrued as diff[t−1] / 252 with no compounding or forward points; a day is a row, dates only define calendar months. Out of scope: missing-data handling, market impact or bid/ask asymmetry, position limits, financing, FX quote conventions, non-Gaussian emissions, multiple random restarts (EM reaches one deterministic local optimum), and label-switching warnings between refits. No upper bound on K is enforced — K = 20 on 504 points will fit and over-fit.

References

Baum, Petrie, Soules & Weiss (1970); Rabiner (1989) for scaling, re-estimation and the zero-mass discussion behind the dead-state guard; Bilmes (1998); Viterbi (1967); Hamilton (1989) for filtered regime probabilities; Akaike (1974); Schwarz (1978); Hyndman & Fan (1996); Moskowitz, Ooi & Pedersen (2012); Hurst, Ooi & Pedersen (2017); RiskMetrics (1996); Fama (1984); Brunnermeier, Nagel & Pedersen (2008); Lustig, Roussanov & Verdelhan (2011); Sharpe (1994); Bishop, Hamilton (1994), Ang & Bekaert and López de Prado as background.

Quick start

git clone https://github.com/AshJha0/regime-aware-trading && cd regime-aware-trading

# Python reference (3.11, numpy >= 1.24, pandas >= 2.0, pytest)
cd python
PYTHONPATH=src python3 demo.py          # end-to-end demo
PYTHONPATH=src python3 -m pytest -q     # test suite (74 tests)
cd ..

# C++ (C++17, CMake >= 3.20, GoogleTest)
cd cpp
bash build.sh                           # cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j2
./build/demo                            # demo
ctest --test-dir build --output-on-failure   # tests (GoogleTest, 69 tests in one binary)
cd ..

# Rust (edition 2021)
cd rust
cargo build --release                   # zero warnings
cargo run --release --bin demo          # demo
cargo test --release                    # 70 integration tests
cd ..

# Java (21, JUnit 4 + Hamcrest — no Maven/Gradle)
cd java
bash build.sh                           # javac -Xlint:all -Werror into out/
bash demo.sh                            # demo main
bash test.sh                            # JUnitCore on all *Test classes (70 tests)
cd ..

# cookbook snippets, after the three native builds (56 snippets)
python3 tools/check_cookbook.py
